Document privacy / Independent project

ShareGuard

A prototype for reviewing document traces before sharing a DOCX file.

View source code ↗ Demo & visual overview ↓

The problem

A document can look ready to share while retaining internal comments, identifying metadata, revisions or hidden text. Those traces can reveal information intended only for the team.

Guide a person through inspecting a DOCX file, reviewing findings, cleaning a copy and verifying supported changes locally.

Scope from the project brief

These are the intended capabilities. Implementation details will be confirmed during the local walkthrough.

Inspection

Look for supported author metadata, comments, tracked changes and hidden text.

Human review

Explain findings and let the user select supported cleanup actions.

Clean and verify

Preserve the original, write a separate copy and inspect supported findings again.

A decision to examine

The intended workflow preserves the original and keeps cleanup choices with the user. Accepting revisions or removing hidden text can affect meaning, so the walkthrough must establish exactly which actions this version supports.

Reflection

After testing with a sample DOCX file, I’ll document which traces were found, which cleanup actions were supported, and what verification could and could not establish.

Limitations

Supported DOCX findings have a defined scope. A clean report should not be presented as a guarantee that every possible sensitive detail has been removed.
