Application security / Independent project

AccessProof

A prototype for comparing intended API permissions with observed access.

View source code ↗Demo & visual overview ↓

The problem

Application changes can accidentally expose another user’s private record or an administrator-only function. A developer needs a repeatable way to compare expected permissions with actual behavior.

Make authorization expectations explicit and turn unexpected access into an understandable regression finding.

Scope from the project brief

These are the intended capabilities. Implementation details will be confirmed during the local walkthrough.

Declared expectations

Describe endpoints, test identities, resource ownership and permission rules in validated configuration.

Read-only checks

Start with known sample resources and GET requests across ordinary users, administrator and anonymous access.

Repeatable results

Produce findings developers can review locally and eventually use in CI, keeping credentials outside committed configuration.

A decision to examine

The brief starts with known resources and read-only requests to keep scenarios focused. The walkthrough will examine how the implementation distinguishes an expected denial from an unrelated server error.

Reflection

After a local run, I’ll explain one identity–resource test, its expected result, what the tool observed, and what that check leaves outside its coverage.

Limitations

A passing configured scenario does not prove that the entire application is secure. Coverage depends on the identities, resources and expectations supplied by the developer.
